Pik의 iOS·Android 첫 출시 기능을 논리 API 단위로 정의한다. 각 기능은 호출 구분, 권한, 입력, 검증, 처리, 트랜잭션, 반환과 예외를 포함한다. 단말 안에서 끝나는 기능, 서버 호출, OS 연계 작업을 구분한다. REST 경로·DTO·물리 테이블은 이 계약을 바탕으로 별도 설계한다.

기능 범위는 기존 결정 기준이다. 오류 코드·상태명·처리 위치·버전 검사·중복 방지·트랜잭션 경계는 구현을 위한 설계 초안이다. 미정 정책은 P01\~P12로 연결하며 해당 값이 필요한 기능은 정책 확정 후 인수 조건을 완성한다. 작성 기준일은 2026년 10월 25일이다.

# 사진 생성부터 액션과 이벤트 자동 제시

[자동 생성 플로우 보기](https://www.figma.com/design/Xwx9heD9ZmRJQK17drYfIL/Pik-Icon?node-id=55-326)

사진이 보관함에 추가되면 사용자의 정리 시작·상세 진입·생성 버튼 없이 아래 흐름을 실행한다. 대상은 촬영·스크린샷·다른 앱 저장·가져오기로 추가된 정지 사진이다. 최초 실행의 기존 사진은 기존 체험 범위와 Pro 우선순위·처리량으로 접수한다.

사진 추가 → 변경 감지·누락 대조 → 이용 자격 확인·작업 접수 → 원본 준비·OCR·맥락 분석 → 액션과 이벤트 독립 생성·저장 → 사진 상세의 액션과 홈의 이벤트에 반영.

## FR-G-01 새 사진 감지와 자동 분석 연결하기

- 호출: OS 변경 이벤트·실행/복귀 시 대조·허용된 백그라운드 작업. G-01.

- 권한: 사진 접근, 외부 분석에는 별도 동의, 체험 대상 또는 현재 유효한 Pro 처리량을 확인한다.

- 입력: 현재 보관함 목록·변경 정보, 사진 ID·원본 버전·추가 확인 시각과 마지막 대조 기준을 받는다.

- 검증: 새 자산·기존 사진 수정·원본 다운로드 완료를 구분한다. 같은 사진·버전을 중복 접수하지 않는다. 한도와 동의는 실제 외부 전송 직전 재확인한다.

- 처리: FR-L-01의 변경 결과를 FR-I-01에 자동 연결한다. 원본 준비 후 FR-I-02·03을 수행하고 분석 결과를 FR-G-02·03으로 분기한다. 대표의 공통 맥락과 선택 사진의 개별 문자·번호를 구분한다. 정리를 하지 않은 사진도 대상이다.

- 트랜잭션: 감지·접수 상태와 작업 식별자를 저장한다. 누락 대조 기준은 처리 대상 기록과 함께 갱신하며 원본 대기·실패 항목은 재개 대상으로 유지한다. 분석 결과와 두 후속 실행 의도를 함께 기록하고 각 생성은 독립 처리한다.

- 반환: 사진별 대기·원본 준비 중·분석 중·완료·실패·자격 미충족 상태를 반환한다. 상세 진입을 생성 트리거로 요구하지 않는다.

- 예외: OS 실행 제약으로 사진 추가 직후 앱이 깨어나지 못하면 다음 실행·복귀에서 누락분을 자동 보충한다. 무조건 즉시 처리·정시 완료를 약속하지 않는다. 분석 접수가 허용된 마지막 체험 사진은 결과 생성 때 한도를 다시 차감하거나 잔여량 0만으로 파생 결과를 버리지 않는다. 실제 만료·동의 철회·탈퇴 시 처리 정책은 기존 P03·P08에 따른다.

## FR-G-02 사진별 액션 자동 생성과 저장하기

- 호출: 분석 완료 내부 이벤트와 허용된 재처리. G-02. 기존 FR-X-01\~07은 생성된 액션의 실행·웹 탐색에 사용한다.

- 권한: 허용된 분석 작업의 출처·동의·현재 계정 상태를 확인한다. 생성 과정에서 체험 사진 수를 중복 차감하지 않는다.

- 입력: 사진 ID·버전, OCR·맥락·의도·분석 출처, 기존 액션과 생성 작업 ID를 받는다.

- 검증: 해당 사진에서 확인한 텍스트·계좌·전화·일정인지 확인한다. 대표 사진의 다른 번호를 구성 사진에 그대로 적용하지 않는다. 추정·불확실 값을 확인된 실행 데이터로 저장하지 않는다.

- 처리: 근거가 있는 복사·전화·지도·일정·번역·웹 액션을 자동 구성한다. 웹 연결은 FR-X-06을 생성 과정에서 호출해 실제 판매·해당 공연 예매 상세 목적지와 후보를 미리 찾는다. 액션 생성은 실제 전화·클립보드 복사·캘린더 등록·구매·브라우저 열기를 수행하지 않는다.

- 트랜잭션: 사진·액션 유형·대상·생성 버전을 기준으로 추가·갱신하고 실행 데이터·출처·준비 상태를 함께 저장한다. 외부 탐색 후 최신 사진·계정 상태를 확인한다. 이벤트 생성의 성공 여부와 독립적으로 결과를 확정한다.

- 반환: 액션 ID·유형·사진 연결·표시 제목·실행 데이터와 준비 완료/링크 탐색 중/확인 필요/생성 실패/대상 없음 상태를 반환한다. 상태명은 설계 초안이다.

- 예외: 근거 없는 사진은 액션 없음이 정상이다. 링크 없음·후보 다수는 임의 URL로 확정하지 않는다. 실패한 종류만 허용 범위에서 재시도한다. 번역 생성과 웹 탐색의 호출 방식·비용은 P03에서 정하며 신규 작업 제한을 우회하지 않는다.

## FR-G-03 이벤트 자동 생성과 기존 이벤트 갱신하기

- 호출: 분석 완료 내부 이벤트. G-03. FR-E-01의 입력과 저장 절차를 구체화한다.

- 권한: 허용된 분석 결과를 이용한다. 캘린더·위치 권한 거절은 생성 전체를 중단시키지 않는다.

- 입력: 새 사진의 ID·의도·OCR·날짜·시간·장소와 기존 이벤트, 허용된 캘린더, 사용자 수정·제외·숨김·완료 상태를 받는다.

- 검증: 관련 사진을 같은 실제 일정·목적으로 묶을 근거를 확인한다. 비슷한 이미지라는 이유만으로 다른 공연·날짜·티켓을 같은 이벤트로 합치지 않는다. 병합 판단 기준·임계값은 P05에서 정한다.

- 처리: 근거가 있는 이벤트 후보를 만들고 기존 동일 일정·목적 이벤트에 사진을 연결하거나 새 이벤트를 생성한다. 확인된 시간 유무를 별도 저장한다. 날짜 없는 유효한 의도 묶음은 홈 카드 대상이며 자동 시간·장소 알림 대상은 아니다.

- 트랜잭션: 이벤트 ID·이름·의도·구성 사진·시점의 확인 여부·출처·버전과 홈 갱신 의도를 함께 저장한다. 날짜가 확인되면 FR-N-02에 알림 예약을 별도로 요청한다. 액션 생성 실패를 이유로 이벤트 저장을 취소하지 않는다.

- 반환: 생성/갱신한 이벤트, 구성 사진과 홈 제시 가능 여부 또는 생성할 근거 없음 결과를 반환한다.

- 예외: 사용자 수정·제외·숨김·완료를 자동 분석이 덮어쓰지 않는다. 재분석·늦은 응답으로 같은 이벤트를 중복 생성하거나 완료·숨김 상태를 되살리지 않는다. 해당 이벤트에 대한 사용자 제외 사진을 자동 재연결하지 않는다. 원본 변경·삭제·권한 철회 시 연결과 표시를 재검증한다.

## FR-G-04 홈 이벤트와 사진 상세 액션 반영하기

- 호출: Query와 저장 완료 후 화면 갱신. G-02·G-03, E-01, X-01\~06.

- 권한: 해당 사진·기존 결과의 소유 범위를 확인한다. 만료 후에도 유지되는 기존 액션·이벤트의 조회를 허용한다.

- 입력: 홈 진입 또는 현재 사진 ID, 저장 결과 버전과 현재 화면 상태를 받는다.

- 검증: 사진 존재·접근·최신 생성 상태, 이벤트의 숨김·완료 상태와 구성 사진을 확인한다.

- 처리: 홈은 FR-E-02로 저장된 이벤트 카드를 조회하고, 사진 상세는 현재 photoId에 연결된 준비된 액션을 하단에 제시한다. 화면을 보는 중 생성이 완료되면 해당 영역을 갱신한다. 홈·상세를 여는 행위는 새로운 분석이나 생성의 필수 조건이 아니다.

- 트랜잭션: 조회는 원본·사용자 선택을 변경하지 않는다. 화면 갱신 실패는 저장 성공을 취소하지 않으며 다음 조회에서 저장 결과를 복구한다.

- 반환: 홈의 이벤트 목록·사진 상세의 액션 목록과 해당 영역의 준비 중/결과 없음/실패를 구분할 상태를 반환한다.

- 예외: 자동으로 생성할 내용이 없는 정상 상태와 처리 장애를 구분한다. 생성 대기 중 실행 불가능한 액션을 준비된 버튼처럼 제시하지 않는다. 이미 준비된 결과는 다른 생성 작업을 기다리지 않고 제공한다.

## 자동 생성 흐름 검증

- 콘서트 포스터가 보관함에 추가되면 별도 생성 요청 없이 분석 작업이 접수된다. 해당 공연 예매 목적지가 준비되면 사진 상세에 액션이, 관련 일정 이벤트가 저장되면 홈에 카드가 표시된다.

- 앱이 닫힌 동안 추가된 사진은 OS 실행 기회 또는 다음 앱 실행·복귀에서 누락 확인 후 자동 처리한다.

- 액션 생성만 실패해도 이벤트는 홈에 표시되고 액션만 재시도한다. 이벤트 생성만 실패하면 준비된 액션은 상세에서 이용한다.

- 같은 사진 변경 알림을 두 번 받아도 분석·액션·이벤트를 중복 생성하지 않는다.

- 완료·숨김·사진 제외를 적용한 이벤트는 늦은 분석 결과로 복구되지 않는다.

- 무료 체험·동의·Pro 처리량 제한은 신규 접수에 적용하며, 이미 허용된 분석 사진의 결과 생성을 별도 새 사진 분석으로 집계하지 않는다.

# 공통 호출과 상태 규칙

## 호출과 데이터 소유 범위

- Query는 현재 정보를 조회하고 Command는 사용자 상태나 외부 작업을 변경한다. 별도 표시가 없는 조회는 사진 이동·삭제·정리 완료·신규 유료 분석을 발생시키지 않는다. 외부 웹 탐색처럼 비용이 발생하는 조회는 해당 기능에서 별도 검증한다.

- Internal Event는 저장된 변화에 반응하는 내부 처리이며 Batch는 누락·기한 도달·남은 대상을 반복 점검하는 처리다. 독립된 조회용 DB나 이벤트 브로커 채택은 부하·유실 복구 요구를 보고 결정한다.

- 사진 원본·실제 앨범 구성은 OS를 기준으로 재조회한다. 메모·태그·정리 상태·분석 출처는 Pik이 관리한다. Pik의 photoId와 기기별 OS 사진 식별자를 분리하며 같은 사진의 다른 기기 ID는 별도 매칭한다.

- 비로그인 메타데이터는 기기에서 유지하고, 로그인한 계정의 메타데이터를 서버에 동기화한다. 비로그인 외부 분석에는 로그인과 별개인 작업 주체 식별을 사용한다. 익명 요청 식별·임시 처리 데이터 보관은 P08의 설계 대상이다.

- 계정 또는 비로그인 이용 주체가 다른 데이터는 자동 병합하지 않는다. 입력 ID만으로 소유권을 인정하지 않는다. 사진 접근 권한과 외부 AI 동의도 별도로 검증한다.

## 트랜잭션과 재시도

- 하나의 DB 트랜잭션은 해당 저장소 안에서 함께 확정할 상태만 포함한다. OS 사진 변경·AI 요청·브라우저/전화 실행·플랫폼 결제를 Pik DB 트랜잭션으로 원자 처리하지 않는다.

- 외부 작업은 실행 의도 저장, 외부 호출, 실제 결과 확인, 결과 기록으로 나눈다. 중단 시 결과를 재대조하고 미확인 결과는 확인 필요 상태로 유지한다.

- 변경 요청은 작업 식별자와 데이터 버전을 사용한다. 같은 작업 재전송은 중복 이동·삭제·과금·일정 등록을 발생시키지 않도록 이미 수행한 단계와 대조한다. 식별자 형식과 보관 기간은 구현 설계에서 정한다.

- 일부 성공이 가능한 작업 목록은 사진별 성공·실패·취소·확인 필요 결과를 제공한다. 이미 성공한 항목을 실패 항목의 재시도에 포함하지 않는다.

- 로컬 저장과 서버 동기화는 별도 완료 상태다. 로컬 저장 성공을 서버 보관 성공으로 표시하지 않는다. 서버 저장과 후속 작업 요청이 분리되며 유실될 수 있는 경우 함께 기록한 실행 의도를 재처리한다.

- 외부 앱이 열렸다는 결과는 통화·공유·구매·예매 완료를 의미하지 않는다. 확인 가능한 수준의 결과만 반환한다.

## 공통 오류와 결과

| 분류 | 의미 | 서버 HTTP 사용 시 매핑 초안 |
| - | - | - |
| INVALID_INPUT | 필수 입력 누락·유효하지 않은 값 | 400 |
| UNAUTHENTICATED | 로그인 전용 호출의 세션 부재·만료 | 401 |
| FORBIDDEN 또는 PERMISSION_REQUIRED | 기능 권한 또는 필요한 OS 권한 부재 | 403 또는 단말의 권한 결과 |
| NOT_FOUND | 소유 범위에서 대상 부재가 확인됨 | 404 |
| CONFLICT | 버전 충돌·이미 반영 중·허용하지 않는 상태 전이 | 409 |
| UNSUPPORTED_OPERATION | 해당 OS·앨범에서 요청한 동작을 지원하지 않음 | 422 또는 단말 결과 |
| TEMPORARY_FAILURE | 통신·외부 처리·일시적 저장 장애 | 503 또는 단말 결과 |

빈 검색 결과와 사용자 취소는 정상 결과로 구분한다. 장기 작업 접수는 작업 ID와 진행 상태를 반환하며 완료를 의미하지 않는다. 공통 응답에는 작업 ID, 결과 상태, 대상별 사유, 재시도 가능 여부를 포함한다. 사진·계정·OCR 본문 전체를 장애 로그의 기본 값으로 저장하지 않는다.

# 사진 보관함과 앨범

연결 시나리오: L-01\~L-04. 사진 원본은 OS 보관함에 두며 Pik은 사진 식별 연결과 추가 정보를 관리한다.

## FR-L-01 사진 보관함과 앨범 동기화하기

- 호출: Command/변경 이벤트, 단말과 OS.

- 권한: 사진 전체 접근을 허용한 사용자. 로그인은 필수가 아니다.

- 입력: 현재 사진 접근 상태, 이전 조회 기준과 OS 변경 정보를 받는다.

- 검증: 접근 가능한 정지 사진인지 확인한다. 동영상은 제외하고 Live Photos는 정지 이미지 부분을 대상으로 한다.

- 처리: 사진과 앨범 목록·구성 관계를 다시 조회한다. 신규·수정·접근 불가·삭제를 구분하고 Pik의 사진 ID와 현재 기기의 OS 식별자를 연결한다. 접근 권한 축소를 원본 삭제로 단정하지 않는다.

- 트랜잭션: 확인된 OS 상태와 로컬 연결 정보를 갱신한다. 분석·검색 갱신은 별도 작업으로 전달한다. 한 번에 전체 원본을 메모리에 읽지 않는다.

- 반환: 현재 접근 범위, 변경된 사진·앨범 ID, 동기화 상태를 반환한다.

- 예외: 접근 거절·원본 다운로드 필요·조회 실패를 구분한다. 실패한 조회 결과로 기존 사용자 메타데이터를 일괄 삭제하지 않는다. 앨범 이동·Live Photos 보존의 플랫폼별 지원은 P06에서 검증한다.

## FR-L-02 사진 목록 조회하기

- 호출: Query, 단말 조회. L-01.

- 권한: 비로그인·무료·Pro 모두 이용한다.

- 입력: 전체/앨범 ID/태그 ID/앨범·태그 조합, 최신순 또는 오래된순, 페이지 조건을 받는다.

- 검증: 조건 형식, 태그·앨범 접근 가능 여부와 페이지 범위를 확인한다. 다중 태그의 AND/OR 의미와 페이지 크기는 P10에서 정한다.

- 처리: 조건에 맞는 개별 사진을 조회한다. 기본 정렬은 최신순이다. 대표 묶음으로 합치는 처리는 검색 결과에만 적용한다.

- 트랜잭션: 읽기만 수행한다. 조회로 정리 완료·분석 한도 차감을 발생시키지 않는다.

- 반환: 사진 ID, 썸네일 참조, 생성 시각, 다음 페이지 정보와 적용 조건을 반환한다. 정렬의 동률 보조키를 고정해 페이지 간 중복·누락을 줄인다.

- 예외: 조건에 맞는 사진이 없으면 빈 목록을 반환한다. 잘못된 조건은 INVALID_INPUT, 접근 불가는 PERMISSION_REQUIRED로 구분한다.

## FR-L-03 사진 상세와 공유용 원본 조회하기

- 호출: Query와 OS 공유 호출, 단말. L-02.

- 권한: 해당 사진에 접근 가능한 사용자.

- 입력: 사진 ID, 상세/원본 보기/공유 목적을 받는다.

- 검증: 현재 사진 식별 연결, 원본 접근 가능 여부를 확인한다.

- 처리: 원본 또는 보기 크기에 맞는 이미지를 불러오고 날짜·위치 등 제공 가능한 기본 정보와 메모·태그를 조합한다. 공유 선택 시 OS 공유 절차로 넘긴다. 사진 분석의 원시 데이터는 별도 상세 기능으로 노출하지 않는다.

- 트랜잭션: 읽기·공유만으로 원본·정리 상태를 변경하지 않는다.

- 반환: 사진 표시 데이터, 기본 정보, 메모·태그, 기능별 이용 가능 상태와 공유 호출 결과를 반환한다.

- 예외: 원본 부재·로딩 실패·공유 취소를 구분한다. 공유창 열림을 실제 공유 완료로 단정하지 않는다.

## FR-L-04 앨범 목록 조회와 새 앨범 생성하기

- 호출: Query/Command, 단말과 OS. L-03.

- 권한: 앨범 조회·생성을 허용한 사용자.

- 입력: 앨범 목록 조건 또는 새 앨범 이름을 받는다. 정리 중에는 새 앨범 생성 의도를 먼저 받는다.

- 검증: 빈 앨범 이름을 거절하고 OS의 앨범 지원 조건을 확인한다. 이름 중복·최대 길이 정책은 P10에서 정한다. 이름이 같은 앨범을 같은 ID로 취급하지 않는다.

- 처리: 선택 목록은 최근 추가한 순을 기준으로 제공한다. 앨범 생성 시각과 사진 추가 시각 중 어느 기준인지, 동률·시각을 알 수 없는 앨범의 정렬은 P10에서 정한다. 새 앨범은 독립 생성 요청 또는 정리 최종 반영에서 생성한다. 태그 생성과 사진 앱 앨범 생성을 구분한다.

- 트랜잭션: 생성 의도를 저장한 뒤 OS 생성 결과를 확인하고 실제 앨범 식별자를 연결한다. 미확인 결과의 재시도에서 중복 앨범을 만들지 않도록 이전 결과를 대조한다.

- 반환: 앨범 ID·이름·지원 가능한 작업, 생성 결과 또는 임시 앨범 참조를 반환한다.

- 예외: OS 거절·미지원·생성 실패를 구분한다. 생성 실패한 앨범으로의 이동은 성공 처리하지 않는다.

## FR-L-05 메모와 태그 저장·제거하기

- 호출: Command, 단말 저장과 로그인 사용자 서버 동기화. L-04.

- 권한: 비로그인·무료·Pro 모두 본인 사진의 정보를 편집한다.

- 입력: 사진 ID, 메모의 새 내용, 추가·제거할 태그, 기존 데이터 버전을 받는다.

- 검증: 사진·태그의 소유 범위를 확인한다. 메모를 보내지 않은 요청과 명시적으로 비운 요청을 구분한다. 문자열 길이·태그 정규화 규칙은 P10에서 정한다.

- 처리: 사용자 입력을 보존하고 앨범 정보와 별도로 저장한다. 동일 사진에 동일 태그 관계를 중복 생성하지 않는다. 기존 분석에 사용자 정보를 추가 반영하는 작업을 요청한다.

- 트랜잭션: 사진별 메모·태그 관계·정보 버전과 후속 갱신 의도를 함께 저장한다. 외부 분석 응답을 기다리는 동안 트랜잭션을 유지하지 않는다.

- 반환: 저장된 메모·태그·버전과 분석·검색 갱신 상태를 반환한다.

- 예외: 다른 변경과 충돌하면 CONFLICT와 현재 버전을 반환한다. 저장 실패 시 입력을 유지한다. 태그 자체 이름 변경·전역 삭제 범위는 P10에서 정한다.

## FR-L-06 사진 원본 삭제하기

- 호출: Command, 단말과 OS. L-02·S-04·E-03의 공통 삭제 기능.

- 권한: 해당 사진에 대한 삭제 권한과 사용자의 명시적인 삭제 확인이 필요하다.

- 입력: 선택한 사진 ID 목록, 삭제 확인과 작업 ID를 받는다.

- 검증: 접근·삭제 가능 여부와 실제 대상 목록을 확인한다. 이벤트에서 제외하거나 앨범 관계만 제거하는 작업과 구분한다.

- 처리: OS의 보관함 삭제 절차를 수행한다. 원본 삭제의 영향 범위를 확인받으며 OS가 최근 삭제 항목으로 보내는 경우 이를 영구 삭제 완료로 표현하지 않는다.

- 트랜잭션: 삭제 의도를 저장하고 OS 결과를 받은 뒤 사진별 성공·실패·취소·확인 필요 상태를 기록한다. 확인되지 않은 원본 삭제를 로컬 기록만으로 완료 처리하지 않는다.

- 반환: 사진별 결과, 실패 사유와 재시도 가능 여부를 반환한다.

- 예외: 사용자 취소는 오류와 구분한다. 일부만 성공하면 성공 항목을 재삭제하지 않는다. Pik 메타데이터의 삭제·보존 시점은 P11에 따른다.

# 사진 정리

연결 시나리오: C-01\~C-05. 정리 상태의 키는 사진 ID와 원본 앨범 ID의 조합이다. 나중에를 제외한 결과는 실제 반영에 성공한 뒤 해당 조합의 완료로 기록한다. 정리 가능·가능 시점·완료는 시스템 상태이며 사용자가 작성하는 태그와 분리한다.

## FR-C-01 정리 세션 시작하기

- 호출: Command, 단말. C-01.

- 권한: 사진 접근이 가능한 모든 사용자. 무료 분석 한도와 수동 정리 횟수는 별개다.

- 입력: 원본 앨범 ID와 작업 단위 50·100·200·300 중 하나를 받는다.

- 검증: 앨범 존재·접근 가능 여부와 작업 단위를 검증한다. 기존 미완료 세션이 있으면 이어하기 또는 명시적 취소 경로를 제공한다.

- 처리: 최근 정리한 앨범을 기본값으로 사용하고 최초에는 스크린샷 앨범을 선택한다. 해당 앨범에서 현재 정리 가능한 사진을 개별 카드로 구성한다. 대표 분석 묶음을 카드 하나로 합치지 않는다.

- 트랜잭션: 세션 ID, 원본 앨범, 작업 대상과 순서, 작업 단위, 진행 상태를 로컬에 함께 저장한다. 실제 사진 앱을 수정하지 않는다.

- 반환: 세션 ID, 대상 수, 현재 사진과 이어하기 여부를 반환한다.

- 예외: 대상이 없으면 빈 상태를 반환한다. 선택 단위보다 적은 잔여 사진을 처리하는 규칙은 P04에서 정한다.

## FR-C-02 사진별 정리 선택 임시 저장하기

- 호출: Command, 단말. C-02·C-03.

- 권한: 해당 세션을 진행하는 사용자. Pro 추천 사용 여부와 직접 앨범 선택 권한을 구분한다.

- 입력: 세션 ID·사진 ID, DELETE/MOVE/KEEP/LATER 선택, 목적지 앨범 또는 NEXT_SESSION/5일/7일 유예를 받는다. 상태·열거형 명칭은 설계 초안이다.

- 검증: 세션에 포함된 현재 사진인지, 반영 중이 아닌지 확인한다. MOVE는 목적지, LATER는 유예 선택이 필요하다. KEEP은 앨범 선택 안의 그대로 두기이다.

- 처리: 왼쪽 삭제, 오른쪽 앨범 선택, 위쪽 나중에, 아래쪽 되돌리기에 대응한다. 나중에는 현재 작업에서 넘기며 다음에는 다음 세션부터, 날짜 유예는 해당 시점부터 재등장시킨다. 날짜 계산·시간대는 P04에서 정한다.

- 트랜잭션: 선택·목적지/유예·직전 선택 이력·다음 위치를 함께 임시 저장한다. 완료 상태와 실제 OS 앨범·원본은 바꾸지 않는다. 임시 LATER의 동일 세션 재등장을 막고, 영구 유예 반영 시점은 P04에서 정한다.

- 반환: 저장된 선택, 현재 진행량과 다음 사진을 반환한다.

- 예외: 필수 선택 누락은 INVALID_INPUT, 이미 반영 중이면 CONFLICT이다. 임시 저장 실패를 처리 성공으로 표시하지 않는다.

## FR-C-03 직전 선택 되돌리기

- 호출: Command, 단말. C-03.

- 권한: 진행 중인 본인 세션의 사용자.

- 입력: 세션 ID와 되돌릴 선택 이력을 받는다.

- 검증: 아직 확정 반영되지 않은 선택인지 확인한다. 여러 단계 되돌리기와 세션 간 범위는 P04에서 정한다.

- 처리: 직전 선택을 제거하고 해당 사진을 현재 카드로 복귀시킨다. 임시 목적지·유예와 진행 위치를 함께 되돌린다.

- 트랜잭션: 선택 이력·세션 진행 위치를 로컬에서 함께 갱신한다. 이미 OS에 반영된 삭제·이동을 자동 복구하는 기능으로 사용하지 않는다.

- 반환: 복귀한 사진, 남은 이력과 현재 진행량을 반환한다.

- 예외: 되돌릴 선택이 없으면 이용 불가 상태를 반환한다. 반영 중·완료 항목은 CONFLICT로 구분한다.

## FR-C-04 임시 작업 조회·이어하기·취소하기

- 호출: Query/Command, 단말. C-04.

- 권한: 해당 로컬 작업의 사용자. 로그인 후 다른 기기로 세션까지 복원하는 범위는 P07에서 정한다.

- 입력: 세션 ID와 조회/이어하기/취소 선택, 취소 시 확인을 받는다.

- 검증: 세션의 현재 상태와 OS에서 사진·앨범이 변경되었는지 확인한다.

- 처리: 앱 중단 후 저장된 위치부터 재개한다. 명시적 취소는 미반영 결과가 반영되지 않음을 확인받아 폐기한다. 취소 확인을 닫으면 작업을 유지한다.

- 트랜잭션: 미반영 선택·임시 목적지·진행 위치를 함께 폐기하거나 재개 상태로 바꾼다. 외부 변경으로 사라진 항목을 미완료와 구분한다.

- 반환: 재개할 카드·누적 선택 또는 취소 결과, 접근 불가 항목을 반환한다.

- 예외: 일부 반영된 작업의 성공 결과까지 취소하지 않는다. 반영 실행 중 취소·중단 처리는 실행 상태를 조회해 확정하고 미확인 결과는 재대조한다.

## FR-C-05 정리 결과 조회·반영하기

- 호출: Query/Command, 단말과 OS. C-05.

- 권한: 해당 세션 사용자와 실제 변경에 필요한 OS 권한.

- 입력: 세션 ID, 검토한 결과 버전, 반영 확인과 작업 ID를 받는다.

- 검증: 선택의 유효성, 원본·목적지 접근, 필요한 OS 변경 지원 여부를 다시 확인한다. 반영 중인 동일 작업의 중복 실행을 막는다.

- 처리: 삭제·이동·그대로 두기·유예 결과를 먼저 제공한다. 확인 후 새 앨범 생성과 사진별 작업을 실행한다. 이동은 목적지 보관과 원본 앨범에서의 제거가 모두 확인되어야 성공이다. 스크린샷 스마트 앨범의 복사 후 원본 삭제 우회는 P06의 보존 검증 전 자동 실행하지 않는다.

- 트랜잭션: 로컬 반영 의도·작업 버전을 먼저 저장한다. OS 결과 확인 후 사진별 결과와 정리 상태를 기록한다. KEEP·DELETE·MOVE 성공은 원본 앨범 조합만 완료로 확정한다. LATER는 완료로 만들지 않으며 목적지·다른 기존 앨범 상태는 자동 완료로 바꾸지 않는다.

- 반환: 사진별 성공·실패·취소·확인 필요 상태, 완료 수, 유예 결과와 남은 작업을 반환한다.

- 예외: OS 요청과 로컬 기록 사이 중단 시 실제 결과를 재조회한다. 전체 묶음의 원자적 성공을 약속하지 않으며 부분 성공을 보존한다. 미지원 작업은 UNSUPPORTED_OPERATION으로 표시한다.

## FR-C-06 실패 항목 재시도와 반영 상태 조회하기

- 호출: Query/Command, 단말과 OS. C-05.

- 권한: 본인 정리 작업을 수행한 사용자.

- 입력: 작업 ID와 재시도할 항목 ID를 받는다.

- 검증: 실패·취소·확인 필요 항목인지 확인한다. 성공한 항목은 재실행하지 않는다.

- 처리: 확인 필요 항목은 OS 상태와 먼저 대조한다. 목적지 추가만 성공한 이동은 원본 앨범 제거의 잔여 단계를 구분한다. 실패 원인을 해결한 뒤 남은 변경만 실행한다.

- 트랜잭션: 작업 단계별 결과를 갱신하고 실제로 완료된 항목만 정리 완료 상태와 함께 저장한다. 같은 요청의 반복 수신은 동일한 결과로 수렴시킨다.

- 반환: 최신 사진별 상태, 재시도 결과와 아직 해결되지 않은 사유를 반환한다.

- 예외: 재시도 중 권한 철회·원본 삭제·앨범 삭제를 구분한다. OS 결과를 확인하지 못하면 실패로 단정해 재삭제하지 않고 확인 필요 상태를 유지한다.

# 사진 분석과 분류 추천

연결 시나리오: O-02, C-02, S-01\~S-03, X-01\~X-06, E-01, B-01\~B-04. 분석은 사용자에게 별도 과업으로 요구하지 않고 사용 흐름의 내부 처리로 수행한다.

## FR-I-01 분석 작업 등록하기

- 호출: Internal Event/Batch, 단말과 서버.

- 권한: 사진 접근과 분석 이용 자격을 확인한다. 외부 전송 작업은 별도 동의가 필요하다.

- 입력: 사진 ID·사진 버전·등록 원인, 계정 또는 비로그인 이용 식별자, 동의와 구독·체험 상태를 받는다.

- 검증: 같은 사진 버전의 중복 분석 여부, 무료 대상 또는 Pro 처리량을 확인한다. 동시 요청의 한도 예약과 실제 완료 집계를 구분한다.

- 처리: 최근 추가되는 사진과 정리 중인 사진을 우선한다. 한 번에 전체 원본을 전송하지 않고 제한된 작업 단위로 처리한다. 무료 100장 집계는 P01, Pro 최초·일별 처리량과 이미지 크기는 P03에서 정한다.

- 트랜잭션: 작업·분석 대상 예약·중복 방지 식별자를 함께 저장한다. 외부 호출 전에 현재 동의·이용 자격을 다시 확인한다.

- 반환: 작업 ID, 대기·진행 상태를 반환한다. 초기 무료 화면에는 100장 한도·잔여량을 표시하지 않는다.

- 예외: 한도 소진·구독 만료 시 신규 분석을 중단한다. 재구독 후 우선순위와 제한 안에서 재개한다. 만료 전 시작된 작업의 완료·비용 처리는 P03에서 정한다.

## FR-I-02 유사 사진 묶음과 대표 선정하기

- 호출: Internal Event/Batch, 단말과 분석 처리 계층.

- 권한: 해당 사진을 분석 대상으로 사용할 수 있어야 한다.

- 입력: 사진 ID 목록, 개별 시간·시각적 유사 정보와 기존 묶음 버전을 받는다.

- 검증: 같은 시간대와 시각적 유사 조건을 모두 충족하는지 판단한다. 임계값·대표 선정·재편성 규칙은 P05에서 정한다.

- 처리: 대표·구성 사진·묶음 ID와 직접 분석/결과 재사용 출처를 구분한다. 대표의 공통 분석을 구성 사진에 복사·참조하되 개별 기본 메타데이터·사용자 입력은 덮어쓰지 않는다. 문자·번호가 다른 사진의 액션에는 공통 결과를 무조건 사용하지 않는다.

- 트랜잭션: 묶음 구성·대표·출처·버전을 함께 저장하고 대표 부재·변경 시 검색 갱신을 요청한다. 원본을 합치거나 삭제하지 않는다.

- 반환: 묶음 ID, 대표 ID, 구성 사진 ID와 대표를 포함한 총 수를 반환한다.

- 예외: 대표 분석 실패가 구성 사진의 직접 분석 성공으로 기록되지 않아야 한다. 원본 수정·대표 삭제·문자 차이에 대한 재분석 경계는 P05에서 정한다.

## FR-I-03 이미지·OCR·의도 분석 실행하기

- 호출: 내부 Worker, 온디바이스와 클라우드의 조합.

- 권한: 현재 동의·분석 이용 자격과 작업 소유 범위를 다시 확인한다.

- 입력: 작업 ID, 대표 또는 개별 사진의 표시용 이미지와 메타데이터, 분석 템플릿 버전을 받는다.

- 검증: 원본 버전·입력 형식·크기와 동의 유효성을 확인한다. 허용 크기·형식·실행 단위·시간 제한은 P03에서 정한다.

- 처리: 내용·요소·관계·행동·분위기·텍스트·시간/장소·저장 의도를 추출한다. 추정 정보와 실제 읽은 정보, 값이 없는 필드를 구분한다. 액션·이벤트·검색용 파생 정보를 생성한다. 확정하지 못한 날짜·번호·링크를 확정값으로 채우지 않는다.

- 트랜잭션: 외부 모델 호출 후 작업 버전·사진 버전과 현재 계정 상태를 대조하고 결과·분석 출처·후속 갱신 의도를 함께 기록한다. 탈퇴 진행·삭제 완료 계정의 늦은 결과는 저장하지 않는다. 외부 요청을 DB 원자적 처리에 포함하지 않는다. 한도 차감·실패 반환 규칙은 P01·P03에서 정한다.

- 반환: 분석 상태·생성한 기능의 이용 가능 여부를 반환한다. 분석 원시 데이터는 일반 화면에 직접 노출하지 않는다.

- 예외: 네트워크·모델·입력 실패와 동의 거절을 구분한다. 불확실한 외부 요청의 무조건 재호출로 비용이 중복되지 않도록 작업 이력을 대조한다.

## FR-I-04 사용자 정보 변경 후 파생 정보 갱신하기

- 호출: Internal Event, 단말·서버. L-04.

- 권한: 해당 사진 정보의 소유자.

- 입력: 사진 ID, 변경된 앨범·태그·메모, 사용자 정보 버전과 기존 분석 참조를 받는다.

- 검증: 최신 변경과 분석 출처를 확인한다. 예전 작업이 새 사용자 입력을 덮어쓰지 않게 한다.

- 처리: 기존 분석에 사용자 정보를 조합해 검색·추천·이벤트·액션에 반영한다. 이 변경만으로 이미지 전체를 다시 분석하지 않는다. 이용 자격이 없는 신규 클라우드 분석을 우회 실행하지 않는다.

- 트랜잭션: 원본 사용자 입력을 먼저 보존하고 파생 정보·인덱스 반영 상태를 별도로 갱신한다.

- 반환: 저장된 사용자 정보 버전과 기능별 갱신 상태를 반환한다.

- 예외: 파생 정보 갱신 실패에도 저장한 메모·태그를 되돌리지 않는다. 사진 자체 수정에 따른 재분석 정책은 P05에서 정한다.

## FR-I-05 앨범·태그 추천 조회하기

- 호출: Query, 단말 또는 서버. C-02.

- 권한: 정리 추천은 유효한 Pro 사용자에게 제공한다. 무료 검색용 기초 분류와 구분한다.

- 입력: 사진 ID, 현재 분석·사용자 정보 버전, 이용 가능한 앨범 목록을 받는다.

- 검증: Pro 권한과 추천 대상의 접근 가능 여부를 확인한다.

- 처리: 적합한 앨범을 가능성이 높은 순으로 최대 5개와 더보기로 제시한다. 더보기는 전체 앨범·새 앨범 추가로 연결한다. 추천 태그는 사용자 선택으로 저장한다. 추천 조회만으로 사진을 이동하거나 태그를 확정하지 않는다.

- 트랜잭션: 읽기만 수행한다. 사용자가 고른 앨범은 FR-C-02의 임시 선택으로 연결한다.

- 예외: 원본 부재·권한 변경으로 열 수 없는 사진을 안내한다. [설계 제안] 오래된 알림은 현재 상태를 조회해 안내한다.

## FR-A-04 같은 계정의 사진 정보 복원

- 호출: Command. 기기 변경·재설치 후 로그인·사진 전체 접근 허용 시 실행한다.

- 권한: 해당 계정 본인. 기기 보관함 조회에는 사진 전체 접근이 필요하다.

- 입력: 계정, 서버 메타데이터, 현재 기기 사진의 식별 후보 정보.

- 검증: 같은 사진인지 확인한다. OS 로컬 사진 ID가 기기 간 동일하다고 가정하지 않는다.

- 처리: 메모·태그·정리 상태·분석 결과를 같은 사진에 다시 연결한다. 동일 사진 식별 방법은 기술 검증이 필요하다.

- 트랜잭션: 서버 조회와 기기 연결 저장은 분리한다. 사진별 연결 결과를 저장하고 실패분을 재개하는 방식은 제안이다.

- 반환: 연결 완료·미연결 범위와 복원 상태. 사진 원본 내려받기는 제공하지 않는다.

- 예외: 사진 부재·식별 모호·통신 실패를 구분한다. 확인되지 않은 정보를 다른 사진에 임의 연결하지 않는다.

## FR-A-05 회원 탈퇴와 Pik 데이터 삭제

- 호출: Command. 삭제 범위 안내 후 사용자가 최종 확인한 경우 실행한다.

- 권한: 로그인한 계정 본인. 최종 확인을 취소하면 기존 계정을 유지한다.

- 입력: 계정과 탈퇴 최종 확인. 활성 구독 유무는 별도 안내의 입력으로 확인한다.

- 검증: 요청 계정·세션과 삭제 범위를 확인한다. 회원 탈퇴가 플랫폼 구독 취소를 뜻한다고 안내하지 않는다.

- 처리: 삭제 진행 상태에서 신규 분석·동기화 반영을 차단하고 서버·기기의 Pik 메모·태그·정리 상태·분석 결과를 삭제하며 계정을 종료한다. 탈퇴 전 시작된 작업의 늦은 응답으로 정보를 재생성하지 않는다. OS 사진·앨범은 유지한다.

- 트랜잭션: 서버 삭제와 기기 삭제는 분리한다. 삭제 상태·재시도 기록으로 완료를 확인하는 안을 제안한다.

- 반환: 삭제 완료 또는 미완료 상태. 활성 구독의 취소·환불은 플랫폼 절차이며 탈퇴 시 안내·처리 정책은 미정이다.

- 예외: 일부 삭제 실패를 완료로 표시하지 않는다. 삭제 시점·로그 보존·재접속 정책은 후속 설계한다.

# 무료 체험과 Pro 구독

## FR-B-01 최초 체험 대상과 3회 클릭 집계

- 호출: Command. 최초 체험 대상 확정 및 액션·이벤트 클릭 기록에 사용한다. 수동 정리 작업 단위와 별개다.

- 권한: 비로그인 포함 무료 사용자. 외부 분석에는 별도 전송 동의가 필요하다.

- 입력: 체험 대상 사진, 액션 또는 이벤트의 클릭 기록, 현재 체험 상태.

- 검증: 최초 1회 100장이고 월별 초기화하지 않는다. 대표·구성 사진 합계와 기초 검색의 같은 100장 범위는 설계 가정이다.

- 처리: 초기 한도·잔여량은 숨긴다. 액션·이벤트를 합산해 3회 클릭하면 100장 범위와 Pro를 안내한다. 구독을 선택하면 로그인 단계로 연결한다.

- 트랜잭션: 대상 범위·이용량·클릭 수 갱신을 일관되게 저장하는 안을 제안한다. 비로그인 기기 간 한도 유지·부정 이용 정책은 미정이다.

- 반환: 실제 분석 진행과 구독 안내 필요 여부. 닫으면 수동 정리·기존 액션·이벤트·무료 기초 검색을 계속 제공한다.

- 예외: 클릭 중복·실패 포함 기준은 미정이다. 중복 제거는 제안이며 분석 미완료를 완료로 표시하지 않는다.

## FR-B-02 상품·구독 상태와 관리 경로 조회

- 호출: Query. 구독 안내 또는 계정 화면에서 이용 상태·상품·플랫폼 관리 경로를 조회한다.

- 권한: 무료 안내는 비로그인도 조회한다. 계정의 구독 내역은 본인만 조회한다.

- 입력: 플랫폼, 로그인 계정이 있으면 계정, 상품·구독 조회 범위.

- 검증: 월간·연간 제공 상품과 확인된 이용 기간을 조회한다. 가격은 미정이며 임의의 수치를 고정하지 않는다.

- 처리: 확인된 Pro 상태, 월간·연간 상품 정보, 플랫폼 구독 관리·구매 복원 진입을 제공한다.

- 트랜잭션: 조회 자체는 구독 권한을 변경하지 않는다. 외부 상품 조회와 서버 상태 조회를 분리한다.

- 반환: 상품 주기·확인된 가격·구독 유효 기간·관리와 복원 경로 및 확인 상태.

- 예외: 조회 실패는 확인 불가로 표시한다. 관리 화면을 열었다는 이유만으로 구독 상태를 변경하지 않는다.

## FR-B-03 월간·연간 구매와 구매 복원

- 호출: Command. 월간·연간 구독 시작 또는 플랫폼 구매 내역 복원에 사용한다.

- 권한: 로그인 계정 본인. 플랫폼 결제·복원 확인과 서버 검증을 통과해야 Pro를 이용한다.

- 입력: 계정, 플랫폼, 상품, 구매 또는 복원 결과의 검증 정보.

- 검증: 서버가 플랫폼 구매 상태·상품·거래 귀속·유효 기간을 확인한다. 클라이언트의 Pro 값만으로 권한을 부여하지 않는다.

- 처리: 플랫폼 결제·복원을 진행하고 서버 확인 결과에 따라 권한을 반영한다. 이후 최근 추가·정리 사진을 우선 분석한다.

- 트랜잭션: 플랫폼 구매·서버 검증·DB 커밋은 별도 단계다. 검증 완료 거래와 권한을 함께 저장하고 재처리를 허용하는 안을 제안한다.

- 반환: 검증된 구독 상태·기간 또는 확인 대기 상태와 원래 진입 위치. 최초·일별 처리량은 미정인 별도 제한이다.

- 예외: 결제 취소·실패·복원 내역 없음·확인 지연을 구분한다. 플랫폼 성공만으로 서버 권한 확인까지 완료됐다고 표시하지 않는다.

## FR-B-04 플랫폼 구독 상태 변경 반영

- 호출: Internal Event. 갱신·취소·만료 등 플랫폼 구매 상태 변경 알림을 수신해 반영한다.

- 권한: 서버에서 확인한 플랫폼 발신·구매 상태만 신뢰한다. 사용자의 직접 권한 변경은 허용하지 않는다.

- 입력: 플랫폼 알림 식별 정보, 거래와 상품, 계정 연결, 확인된 상태·유효 기간.

- 검증: 발신과 구매를 검증하고 중복·역순 알림을 판별한다. 구체적 판별 키·우선순위는 설계 제안이다.

- 처리: 플랫폼의 확인된 최신 상태를 반영한다. 자동 갱신 취소 요청과 실제 유효 기간 종료를 구분한다.

- 트랜잭션: 알림 처리 이력·구독 상태를 원자 반영하고 동일 알림의 반복 효과를 방지한다. 외부 재확인은 DB 밖에서 수행한다.

- 반환: 반영 완료·이미 처리됨·확인 대기 상태와 갱신된 권한. 응답 형식은 후속 설계한다.

- 예외: 계정 연결 불명·검증 실패·일시 장애는 권한을 임의 확대하지 않는다. 재검증·재시도·정합성 점검 방식은 제안이다.

## FR-B-05 한도 소진·유효 기간 종료 시 기능 제한

- 호출: Internal Event. 체험 한도 소진·확인된 구독 만료에 적용한다. 누락 점검 Batch는 설계 제안이다.

- 권한: 서버가 확인한 체험·구독 상태에 따라 적용한다. 기기 시각이나 취소 버튼 선택만으로 만료를 확정하지 않는다.

- 입력: 체험 대상과 소진 상태, 구독 유효 기간·검증 상태, 처리 대기 작업.

- 검증: 적용 직전에 현재 이용 자격을 다시 확인한다. 유효한 Pro가 있으면 체험 소진을 이유로 권한을 제한하지 않는다. 오래된 만료·소진 이벤트는 최신 갱신·재구독 상태와 대조한다. 로그인과 Pro 권한을 별도 조건으로 판단한다.

- 처리: 신규 분석을 중단하고 Pro 확장 검색·iOS Spotlight 연동을 제한한다. 기존 액션·이벤트·무료 기초 검색·수동 기능은 유지한다.

- 트랜잭션: 권한 변경과 신규 분석 허용 상태를 함께 반영하는 안을 제안한다. 실행 중 작업·OS 인덱스 정리 방식은 기술 검증 대상이다.

- 반환: 유지·제한되는 기능과 재구독 안내. 구매 재검증 후 유효한 Pro이면 정해질 처리량 내 분석·확장 기능을 재개한다.

- 예외: 기존 액션 이용 유지와 신규 실시간 웹 탐색 비용은 미정이다. 만료를 이유로 기존 Pik 결과를 삭제하거나 무료량을 갱신하지 않는다.

# 화면과 제스처 동작

아래 수치는 사용자 원안의 UI 기준을 상세 요구사항 후보로 옮긴 것이다. 현재 기능 정의에서 별도로 확정되지 않은 전환·제스처의 수치는 P12에서 검토한다.

## FR-U-01 앱 화면 크기와 보관함 그리드 조절하기

- 호출: 단말 UI. L-01.

- 권한: 보관함 이용자.

- 입력: 화면·창 크기, 핀치 동작, 이전 격자 설정을 받는다.

- 검증: 열 수를 1\~15 범위로 제한한다. 기본값은 5이며 마지막 설정에 가까운 3 또는 5로 시작한다. 동률 기준은 P12에서 정한다.

- 처리: 일반 칸은 정사각형 Fill로 표시한다. 1열은 전체 이미지가 보이도록 하되 높이를 min(화면 너비×4, 화면 높이×2) 이내로 제한한다. 기본 최신 사진은 그리드 하단, 위로 갈수록 오래된 사진을 보여준다. 오래된순 선택 시 방향·초기 스크롤은 P12에서 정한다. 화면 회전은 지원하지 않으며 창 너비가 높이 이상이면 콘텐츠 너비를 높이에 맞추고 남는 여백을 흰색으로 처리한다.

- 트랜잭션: 그리드 설정을 로컬 저장한다. 사진과 앨범은 변경하지 않는다.

- 반환: 표시할 격자 크기와 스크롤 위치를 제공한다.

- 예외: 최대 높이로 전체 이미지를 표시하지 못하는 1열 사진의 최종 맞춤 규칙, 태블릿·분할 화면과 세로 고정 정책의 적용 범위는 P12에서 정한다.

## FR-U-02 사진 상세 뷰어 조작하기

- 호출: 단말 UI. L-02.

- 권한: 해당 사진 접근 가능 사용자.

- 입력: 한 번 탭·두 번 탭과 선택 위치를 받는다.

- 검증: 이미지 로딩과 현재 확대 상태를 확인한다.

- 처리: 기본은 높이 제한이 있는 Fit이다. 두 번 탭하면 전체 화면으로 확장하고 누른 지점을 중심으로 Fill로 전환한다. 한 번 탭하면 뷰어 외 컨트롤을 숨기거나 다시 보인다. 상단은 뒤로·태그·더보기, 하단은 공유·리마인드·정보·삭제와 허용된 액션을 제공한다. 연관 보기는 제공하지 않는다.

- 트랜잭션: 표시 상태만 변경한다.

- 반환: 이미지 확대·컨트롤 표시 상태를 제공한다.

- 예외: 한 번 탭과 두 번 탭의 충돌 방지, 확대 해제와 상세 화면 복귀 규칙은 P12에서 정한다.

## FR-U-03 정리 카드 제스처와 선택 피드백 제공하기

- 호출: 단말 UI. C-02·C-03.

- 권한: 진행 중인 정리 세션 이용자.

- 입력: 스와이프 방향·거리와 앨범 후보 위의 선택 위치를 받는다.

- 검증: 제스처의 실행 확정 기준과 연속 입력 허용 범위는 P12에서 정한다.

- 처리: 우측 앨범은 세로 목록으로 스크롤한다. Pro는 추천 최대 5개와 더보기, 전체 목록 끝의 추가하기를 제공한다. 후보 위에 위치하면 아이콘을 확대해 선택 대상을 알린다. 위 방향은 기본 5일 뒤, 왼쪽 위는 다음에, 오른쪽 위는 7일 뒤이며 텍스트가 나타나게 한다. 아래 방향은 되돌리기 아이콘을 표시한다. 선택에 맞춰 카드가 스택에서 빠지거나 뒤로 쌓이고 되돌아오는 애니메이션과 짧은 진동을 제공한다.

- 트랜잭션: 애니메이션만으로 선택 저장 성공을 확정하지 않는다. 실제 입력은 FR-C-02·03의 결과와 일치시킨다.

- 반환: 현재 선택 방향·앨범·유예 시점과 처리 결과를 제공한다.

- 예외: 취소한 제스처는 선택을 저장하지 않는다. 정리 카드는 대표 묶음으로 합치지 않는다. 애니메이션 지속 시간·진동 강도와 접근성 설정 대응은 P12에서 정한다.

# 데이터 경계와 후속 처리

아래는 첨부 예시의 aggregate root·트랜잭션·이벤트·배치·삭제 정책을 Pik에 적용한 설계 제안이다. aggregate root는 해당 단위의 변경 규칙과 불변조건을 검증하는 진입점이며 조회 DTO의 크기는 별도 설계한다. 도메인 경계 후보는 사진 연결·정리·분석과 검색·이벤트와 알림·계정과 구독이다. 실제 테이블 수와 배포 서비스 분할은 구현 설계에서 정한다.

## 저장과 일관성의 단위

| 논리 단위 | 함께 관리할 데이터 | 하나의 트랜잭션 경계 |
| - | - | - |
| 사진별 Pik 정보 | photoId, 기기별 OS 연결, 메모·태그 관계, 정보 버전 | 사용자 정보와 갱신 의도. OS 원본은 별도 |
| 정리 세션 | 원본 앨범, 대상 순서, 임시 선택, 되돌리기 이력, 진행 위치 | 임시 선택과 위치. 최종 OS 반영은 사진별 작업 단계로 확인 |
| 정리 상태 | photoId와 원본 albumId, 정리 가능 시점·완료 상태 | 확인된 반영 결과와 해당 조합 상태 |
| 분석 작업과 대표 묶음 | 사진 버전·작업 상태·이용량 예약, 묶음·대표·구성·출처 | 작업 접수/결과 저장, 묶음 구성 갱신. 전체 사진을 한 트랜잭션으로 잠그지 않음 |
| 이벤트 | 이름·일정·구성 사진·완료/숨김 상태·알림 버전 | 이벤트 변경과 알림 무효화 의도 |
| 리마인드 | 명시적 대상·시점·예약 상태 | 리마인드와 OS 예약 의도 |
| 체험·이용 자격 | 최초 체험 범위·사진별 예약/완료·클릭 수·구독 권한 | 중복 요청을 검증한 사용량·권한 상태 |
| 계정과 구독 | 제공자 연결·세션, 거래 검증 결과·유효 기간 | 인증 연결 또는 검증된 거래 반영. 전체 사진 동기화와 별도 |

## 이벤트로 이어서 처리할 항목

- 사진·사용자 메타데이터 변경: 기존 분석에 정보 추가 반영 → 검색·추천·이벤트 갱신.

- 분석 완료: 분석 출처 기록 → 액션·이벤트·검색용 정보 반영. 같은 결과의 재전달은 중복 생성하지 않는다.

- 정리 반영 성공: 사진·앨범 조합 상태 갱신 → 실제 앨범 구성 재조회 → 필요한 인덱스 갱신.

- 이벤트 수정·완료: 알림 버전 갱신 → 기존 예약 무효화/취소 → 허용되는 새 예약만 반영.

- 검증된 구독 변경: 이용 자격 갱신 → 신규 분석 허용/중단 → Pro 검색·Spotlight 사용 범위 갱신.

## 배치로 점검할 항목

- Pro 처리량과 우선순위에 따른 미분석 작업, 허용되는 실패 작업의 재시도.

- 로컬 반영과 서버 동기화의 미완료분, OS 결과 확인 필요 작업.

- 기한이 도달한 유예 상태·리마인드·이벤트 알림, 정리 독려와 권한 설정 요청의 발송 조건.

- 플랫폼 구독 변경 알림 누락과 실제 이용 기간 종료의 재대조.

- 탈퇴·정보 삭제의 미완료분과 보관 기간이 지난 임시 처리 데이터. 배치 주기·재시도 횟수·운영 알림 기준은 P03·P08·P09에서 정한다.

배치는 사용자에게 보이는 결과를 복구·갱신하는 실행 방식이다. 알림을 보냈다고 가정하거나 OS가 백그라운드 실행을 보장한다고 전제하지 않는다.

## 이력과 삭제 정책

- 변경 가능한 Pik 데이터에는 생성·수정 시각과 버전을 관리한다. OS의 촬영·수정 시각과 Pik의 처리 시각을 다른 필드로 구분한다.

- 임시 정리 선택·되돌리기 이력은 재개·확정·취소를 위해 보관한다. 종료 후 보존 기한과 유예의 취소 효과는 P04·P08에서 정한다.

- 태그 연결 해제·이벤트 사진 제외는 관계를 제거한다. 원본 삭제로 전달하지 않는다. 동기화에 삭제 표시가 필요하면 전달 완료까지 tombstone을 유지하고 정해진 기한 후 제거하는 안을 사용한다.

- 이벤트 완료·숨김은 삭제와 다른 업무 상태다. 완료한 이벤트의 알림·삭제 요청을 다시 생성하지 않도록 상태를 보존한다.

- 원본 삭제 확인 후 Pik 사진 정보의 삭제·보존은 P11에서 정한다. 권한 철회·다운로드 불가·기기 미보유는 확인된 원본 삭제와 다르게 처리한다.

- 탈퇴는 Pik 메타데이터·분석 결과·계정의 삭제 흐름이다. 단순 soft delete만으로 데이터 삭제 완료를 표시하지 않는다. 기기·서버·임시 처리 시스템의 미완료분을 추적하며 OS 사진·앨범은 유지한다.

- 결제 검증·중복 방지·삭제 완료 확인에 필요한 최소 기록의 항목·목적·보관 기간은 P08에서 정한다. 원본 사진이나 OCR 본문을 영구 이력으로 보관하는 정책을 전제하지 않는다.

# 검증할 대표 사례

- 무료 100장 분석이 끝나도 200장 단위의 수동 정리 시작을 막지 않는다.

- 같은 사진이 A와 B 앨범에 있을 때 A에서 KEEP을 반영해도 B는 완료가 되지 않는다. A에서 C로 이동을 완료해도 B와 C의 정리 상태를 자동 완료로 바꾸지 않는다.

- 6장 묶음은 검색에서 대표와 숫자 6으로 표시하고 펼치면 6장을 보여준다. 정리에서는 6장 모두 개별 카드로 처리한다.

- 정리 50장 중 48장만 반영되면 48장은 성공 상태로 유지하고 나머지만 재시도한다. 목적지 추가만 확인된 이동은 완전 성공과 구분한다.

- 액션 2회와 이벤트 1회 클릭이 유효 집계 3회가 되면 안내한다. 안내를 닫아도 무료 정리와 기존 결과를 이용한다. 중복·실패 클릭의 집계는 P01 확정값으로 검증한다.

- 이벤트 완료 후 보관하거나 삭제를 취소해도 완료 상태를 유지하고 해당 이벤트의 알림·삭제 요청을 다시 보내지 않는다.

- 외부 분석을 거절하면 전송하지 않고 수동 정리·메모·태그를 유지한다. 사진 접근 허용만으로 외부 전송을 시작하지 않는다.

- 콘서트 포스터의 웹 액션은 해당 공연 예매 상세페이지를 연다. 후보가 모호하면 선택받고 정확한 목적지를 찾지 못하면 실패로 안내한다.

- 계정 복원 시 다른 사진의 메모·계좌번호를 잘못 연결하지 않는다. 사진 원본을 서버에서 복원하는 것으로 표현하지 않는다.

- 회원 탈퇴는 Pik 정보 삭제이며 OS 사진·앨범을 삭제하지 않는다. 플랫폼 구독 상태는 별도 확인한다.
