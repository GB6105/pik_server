# ADR-0019: 알림은 서버 중심으로 전달한다

- 상태: 채택 (제안 확정·발송 대상 기기 결정: ADR-0024)
- 날짜: 2026-10-25
- 관련: FR-N-01~04, FR-E-03·04, P07, P09, ADR-0014, ADR-0016, D-14, 브랜치 `feature/tech-stack-design`

## 맥락
- 알림 전달 방식 (단말 로컬 예약 / silent push / 서버 원격 푸시)이 정해지지 않았다.
- 장소 알림에는 기기 위치, 정리 독려에는 남은 정리 대상과 이용 시점, 권한 요청에는 기기별 권한 상태가 필요하다. 비로그인 사용자의 이벤트·메타데이터는 서버에 없다.
- 요구사항은 이벤트를 완료·수정한 뒤 오래된 알림이 발송되지 않게 하라고 요구한다 (FR-N-02).

## 결정
| 알림 | 로그인 사용자 | 비로그인 사용자 |
|---|---|---|
| 이벤트 시간 알림 (FR-N-02) | 서버가 발송 직전에 이벤트 상태·알림 버전을 확인하고 FCM으로 발송 | 단말 로컬 예약 |
| 이벤트 장소 알림 (FR-N-02) | 단말이 구역 진입을 감지 → 서버에 최신 상태 확인 → 유효할 때만 표시 | 단말 로컬 예약 |
| 정리 독려 (FR-N-03) | 단말이 보고한 남은 정리 대상 수와 마지막 정리·이용 시점으로 서버가 판단해 FCM 발송 | 단말 로컬 예약 |
| 권한 요청 (FR-N-04) | 단말이 보고한 기기별 권한 상태로 서버가 해당 기기에 FCM 발송 | 단말 로컬 예약 |
| 사진 리마인드 (FR-N-01) | 단말 로컬 예약 (단말 전용 FR) | 단말 로컬 예약 |

- 무효화용 silent push는 도입하지 않는다. 분석 완료 화면 갱신은 앱이 열려 있을 때 상태 조회 (ETag)로 처리한다 (제안).
- 서버 발송 구성:
  - 기기별 푸시 토큰 테이블을 둔다. 알림 예약 테이블은 (대상, 알림 종류, 알림 버전) unique 키로 중복 발송을 막는다
  - 이벤트 변경, 알림 버전 증가, 예약 재계산을 한 트랜잭션에서 처리한다
  - `worker` 배치 (1분 간격): 발송 시각이 된 알림을 `SKIP LOCKED`로 가져와 상태·버전을 다시 확인하고, FCM HTTP v1로 발송한 뒤, 미등록 토큰을 삭제한다
  - FCM 메시지 유효 기간은 알림이 의미 있는 시점까지로 둔다 (이벤트 시간 알림은 이벤트 시작 시각)
  - 알림 문구에 이벤트 이름을 넣는다
  - 기기가 여러 대일 때 발송 대상 기기 규칙은 P09와 함께 정한다
- 장소 알림을 서버에 확인하려면 위치 권한 '항상 허용'이 필요하다. '앱 사용 중 허용'이면 서버 확인 없는 OS 위치 알림으로 대신한다. 서버 확인 시점에 오프라인이면 마지막으로 동기화한 상태로 판단한다 (제안).
- 로그인하면 단말은 로컬 시간 알림을 취소하고 서버가 발송을 넘겨받는다. 로그아웃 후 처리는 P07을 확정한 뒤 정한다.

## 근거
- 사용자 결정 (서버 중심 설계). 서버 발송은 발송 직전에 대조하므로 완료·숨김된 이벤트의 알림을 발송 단계에서 막는다.
- silent push 미도입 (제안): 서버가 발송하는 알림은 발송 직전에, 장소 알림은 '항상 허용'인 경우 표시 직전에 서버가 확인한다. 리마인드는 기기 간 동기화 대상이 아니고, 비로그인 사용자는 기기가 하나다. 남는 경로는 '앱 사용 중 허용'인 장소 알림뿐이다. silent push로 이 경로의 오래된 알림을 일부 줄일 수는 있지만 전달이 보장되지 않으므로, 구성 요소를 늘리지 않고 수용 위험으로 기록한다.
- 비로그인 사용자의 알림과 리마인드는 서버에 데이터가 없거나 단말 전용 FR이라 로컬로 둔다.

| 대안 | 버린 이유 |
|---|---|
| 모든 알림을 단말 로컬 예약 | 다른 기기에서 완료·수정한 이벤트의 알림이 앱을 열기 전까지 울림 |
| 로컬 예약 + silent push | iOS가 silent push를 지연·폐기할 수 있고, 앱을 강제 종료하면 전달되지 않음. 서버 중심 설계에서는 필요 없음 |

## 결과
- **SSOT와의 차이:** FR-N-02 원문은 "로컬·서버 조정 후 OS 예약·취소"로 단말 예약을 전제한다. 로그인 사용자의 이벤트 시간 알림을 서버가 발송하는 것은 사용자 결정에 따른 차이다. `docs/spec`는 수정하지 않았다.
- **SSOT와의 차이 (FR-N-04):** FR-N-04는 "발송 시 여전히 미허용인지 확인"을 요구한다. 서버는 단말이 마지막으로 보고한 권한 상태로 판단하므로, 보고 이후 사용자가 설정에서 허용했다면 불필요한 알림이 나갈 수 있다.
- **수용 위험:** '앱 사용 중 허용'인 장소 알림은 서버 확인 없이 표시되므로, 다른 기기에서 완료한 이벤트의 장소 알림이 울릴 수 있다 (FR-N-02 요구 일부 미충족).
- 서버가 발송하는 알림은 발송 시각에 기기가 온라인이어야 받는다. 시각 정확도는 배치 주기 (1분) + FCM 지연이다.
- 알림 문구 (이벤트 이름 포함)는 Apple·Google 푸시 서버를 거치므로 개인정보 처리 고지 (P08)에 포함한다.
- Firebase 서비스 계정과 APNs 키 (Firebase에 등록)가 필요하다.
- 선행 시간·반복·정리 알림 단계는 P09 설정값으로 둔다.
- 플랫폼별 백그라운드 위치·알림 지원 조건은 기술 검증 대상이다.
- 출처: '사용자 결정'으로 적은 항목만 사용자가 직접 정했다. 그 밖의 구성은 Claude 설계안이며, 사용자가 종료 보고에서 이 구성을 확인했다 (2026-10-25). `(제안)` 항목은 정책 판단이나 SSOT 해석이 걸려 있어, 해당 구현을 시작하기 전에 사용자 확인을 받는다 (D-14).
