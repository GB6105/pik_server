# ADR-0018: 구독 검증은 RevenueCat으로 연동한다

- 상태: 채택
- 날짜: 2026-10-25
- 관련: FR-B-02~05, FR-A-01, FR-A-05, P07, P08, ADR-0015, D-12, D-14, 브랜치 `feature/tech-stack-design`

## 맥락
- FR-B-03·04는 서버가 플랫폼 구매 상태·거래 귀속·유효 기간을 확인하고, 중복·역순 알림을 판별하도록 요구한다.
- 선택지: App Store Server Library·Play Developer API 직접 연동 / RevenueCat.

## 결정
- 구독 검증과 플랫폼 알림 처리는 RevenueCat에 맡긴다.
- 서버 처리:
  - RevenueCat 웹훅을 받으면 Authorization 헤더를 검증하고, 이벤트 ID unique 키로 중복을 제거한다
  - 웹훅 본문을 그대로 반영하지 않고, RevenueCat REST API로 구독자의 최신 상태를 다시 조회해 이용 자격에 반영한다 (역순 도착 대응)
  - 만료·웹훅 누락을 재대조하는 배치를 둔다
- RevenueCat app user ID = Pik 계정 ID. 단말은 로그인한 뒤에만 구매를 진행한다 (FR-A-01).
- 구매·복원 직후 단말이 서버에 알리면, 서버는 웹훅을 기다리지 않고 RevenueCat REST API로 바로 재조회해 검증된 상태 또는 `확인 대기`를 반환한다 (FR-B-03, 제안).
- 다른 계정에서 구매를 복원할 때 RevenueCat의 구매 이전 동작은 자동 병합 금지 (CLAUDE.md 불변 규칙)에 맞춰 원래 계정을 유지하는 쪽으로 설정하고, P07 확정 때 다시 검토한다 (제안).
- Apple·Google 결제 자격 증명은 RevenueCat 대시보드에 등록한다. 서버는 RevenueCat secret API 키와 웹훅 인증 값만 보관한다.
- 탈퇴 삭제 작업에 RevenueCat 고객 삭제 호출을 포함한다. 플랫폼 구독 자체는 유지되므로 별도로 안내한다.

## 근거
- 사용자 결정. 유예·환불·결제 재시도 같은 플랫폼별 예외 처리를 직접 구현하지 않아 개발 기간이 줄고, 검증된 처리 결과를 쓴다.
- SSOT 해석: FR-B-03·04의 "서버가 플랫폼 구매 상태를 확인한다"를 "서버가 RevenueCat의 플랫폼 검증 결과를 조회해 확인한다"로 해석한다. 클라이언트 보고만으로 권한을 주지 않는 원칙 (`consistency-rules.md`)은 유지된다.

| 대안 | 버린 이유 |
|---|---|
| 공식 라이브러리 직접 연동 | 외부 처리자는 없지만 플랫폼별 예외 상황을 직접 구현·유지해야 함 |

## 결과
- RevenueCat이 외부 처리자로 추가되므로 개인정보 처리 고지 (P08)에 포함한다.
- 요금제와 계약 조건은 D-12에서 확인한다.
- RevenueCat 장애 시에는 마지막으로 확인된 이용 자격을 그 유효 기간이 끝날 때까지만 유지한다. 권한을 임의로 확대하지 않는다 (FR-B-04 예외). 유효 기간이 지나면 확인될 때까지 Pro 기능을 제한한다 (제안: FR-B-05는 '확인된 만료'에만 제한을 적용하므로, 유예 길이와 함께 확인한다).
- 출처: '사용자 결정'으로 적은 항목만 사용자가 직접 정했다. 그 밖의 구성은 Claude 설계안이며, 사용자가 종료 보고에서 이 구성을 확인했다 (2026-10-25). `(제안)` 항목은 정책 판단이나 SSOT 해석이 걸려 있어, 해당 구현을 시작하기 전에 사용자 확인을 받는다 (D-14).
