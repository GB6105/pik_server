# ADR-0016: 외부 AI 연동, 사진 분석 파이프라인, 외부 전송 동의 범위

- 상태: 채택 (파이프라인 확정·접수 단계 대체: ADR-0021, 웹 탐색 모델·장소 제공자 (Google Places) 확정: ADR-0024)
- 날짜: 2026-10-25
- 관련: FR-G-01~04, FR-I-01~06, FR-O-02, FR-X-05·06, P01, P03, P08, ADR-0014, ADR-0017, D-07, D-08, D-09, D-14, 브랜치 `feature/tech-stack-design`

## 맥락
- 사진 분석 (FR-I-03)에는 이미지·OCR·의도 추출이 필요하다. 장당 비용과 지연이 서버 비용과 응답성을 좌우한다.
- 외부 전송에는 FR-O-02 동의가 필요하다. 동의 안내에 무엇을 어디로 보내는지 정해야 한다.

## 결정
### 모델
| 경로 | 모델 | 비고 |
|---|---|---|
| 사진 분석 | Claude Haiku 5.5 (`claude-haiku-5-5`)로 시작 | 실제 사진 표본으로 측정한 뒤 재결정 (D-07) |
| 웹페이지 후보 (FR-X-06) | Claude + `web_search`·`web_fetch` 서버 도구 | 최신 도구 버전은 Opus·Sonnet 계열만 지원 (Claude API 문서, 2026-10-25 확인). Haiku 지원 여부를 측정하고, 지원하지 않으면 이 경로만 Sonnet 5.5 (제안) |
| 검색어 해석 | Jev (TypeSafe). Pro는 Jev + LLM (LLM = Haiku 5.5는 제안) | ADR-0017 |

- 모델 ID는 경로별 설정값 (`pik.ai.*`)으로 분리해 코드 수정 없이 교체한다.
- 측정 지표: 번호·날짜 정확도, 추정값을 확정값으로 저장한 비율, 장당 비용, 지연.
- Haiku 5.5는 거절 응답의 서버 측 자동 대체 기능이 없다 (Claude API 문서, 2026-10-25 확인). `stop_reason: refusal`은 `분석 실패 (사유 코드)` 상태로 저장한다.

### 파이프라인 (ADR-0021에서 확정. 1단계는 ADR-0021의 분석 접수 흐름으로 대체)
1. 접수: `POST /analysis-jobs` (`Idempotency-Key`, photoId, 사진 버전) → 작업 (PENDING)·이용량 예약·멱등 기록을 한 트랜잭션에 저장 → 202 + 작업 ID + 진행 상태 + S3 presigned PUT URL
2. 업로드: 단말이 축소 이미지 (JPEG·WebP)를 S3에 직접 올린다. API 서버는 이미지 바이트를 다루지 않는다
3. 실행 (`worker`): 우선순위 (최근 추가 > 정리 중 > Pro 처리량) 순으로 `SKIP LOCKED` 획득 → 동의·이용 자격 재확인 → 호출 의도 기록 → Claude 호출 (structured output, 고정 system prompt 캐싱) → 사진·작업 버전과 계정 상태를 대조한 뒤 결과 + 후속 이벤트 저장 → S3 객체 삭제
4. 후속: 액션 생성과 이벤트 생성 리스너가 독립 실행한다. (photoId, 유형, 생성 버전) unique 키로 중복 생성을 막는다
5. 결과 불명 (타임아웃 등)은 `확인 필요` 상태로 두고 재대조 배치가 처리한다. 무조건 재호출하지 않는다
6. 대량 백로그 (최초 실행 때의 기존 사진, Pro 최초 처리량)는 Message Batches API로 보낸다

- 묶음 판단은 서버가 하고 단말은 대표만 올린다 (ADR-0021). 단말 OCR 여부와 축소 해상도는 클라이언트와 합의할 대상이다 (D-09).

### 외부 전송 동의 범위 (FR-O-02 안내)
| 보내는 데이터 | 받는 곳 | 용도 |
|---|---|---|
| 사진 축소본, OCR 텍스트 (단말 OCR 채택 시, D-09) | Anthropic (Claude) | 사진 분석, 액션·이벤트 생성 |
| 검색어, 앨범 이름 | TypeSafe (Jev) | 검색어와 관련 있는 폴더 판단 (Basic·Pro) |
| 검색어 | Anthropic (Claude) | Pro 검색어 속성 추출 |

- Anthropic은 국외에서 처리하므로 (`inference_geo` = global·us) 안내에 국외 이전을 고지한다. TypeSafe의 데이터 보관·처리 국가는 공식 문서에 없어 (docs.typesafe.ai/api, 2026-10-25 확인), D-08에서 확인한 뒤 국외 이전 여부와 안내 문구를 확정한다.
- 동의하지 않은 사용자에게는 사진 분석과 자연어 검색을 제공하지 않는다. 속성 검색과 수동 기능은 유지한다. 자연어 검색 비제공은 사용자가 확정했다 (ADR-0021).
- 사진은 Jev로 보내지 않는다.

## 근거
- Haiku 5.5로 시작: 사용자 결정. 장당 추정 비용 (입력 1,500 + 출력 500토큰 가정)은 Opus 5.5 약 $0.016, Sonnet 5.5 약 $0.008, Haiku 5.5 약 $0.0004이며, 무료 100장 체험 비용에 직접 영향을 준다. 추론 토큰도 출력으로 과금되므로 실제 비용은 더 클 수 있다. 정확도와 실제 비용은 측정으로 확인한다. 단가 출처: Claude API 가격표 (2026-10 기준).
- presigned 직접 업로드: API 인스턴스가 대용량 요청을 처리하지 않아 응답성이 유지된다.
- 이미지 축소: 이미지 토큰은 해상도에 비례한다 (1280×720 약 1,200토큰, 장변 2576px 최대 약 4,784토큰, Claude API 문서, 2026-10-25 확인). HEIC는 Claude 입력 형식이 아니므로 단말에서 변환한다.
- Message Batches: 비용이 50%이고 비동기로 처리된다 (Claude API 문서, 2026-10-25 확인). 정시 완료를 약속하지 않는 요구사항 (FR-G-01)과 맞는다.
- 검색어·앨범 이름 고지: 사용자 결정. 표에 없는 외부 전송 (장소 해석 제공자, D-10)은 그 결정 때 동의 범위를 다시 검토한다.

| 대안 | 버린 이유 |
|---|---|
| Opus 5.5·Sonnet 5.5로 시작 | 비용이 높음. 측정한 뒤 필요한 경로만 상향 (D-07) |
| API 서버를 거치는 업로드 | 이미지 바이트가 API 인스턴스의 메모리·대역폭을 차지 |
| 사진을 Jev로 분류 | 사용자 결정 (Jev 역할 = 검색어 해석, ADR-0017). Jev 이미지 입력은 별도 헤더 (`TypeSafe-Danger-Zone-Images`)가 필요한 기능이기도 함 (docs.typesafe.ai/api, 2026-10-25 확인) |

## 결과
- 분석 작업 상태는 FR-G-01 반환 상태 (대기·원본 준비 중·분석 중·완료·실패·자격 미충족)에 `확인 필요`를 더한다. 상태명은 구현할 때 확정한다.
- 로그에 사진·OCR 본문·검색어·앨범 이름을 기록하지 않는다.
- 임시 이미지 보관 기간과 동의 철회 시 처리는 P08 설정값으로 둔다.
- 출처: '사용자 결정'으로 적은 항목만 사용자가 직접 정했다. 그 밖의 구성은 Claude 설계안이며, 사용자가 종료 보고에서 이 구성을 확인했다 (2026-10-25). `(제안)` 항목은 정책 판단이나 SSOT 해석이 걸려 있어, 해당 구현을 시작하기 전에 사용자 확인을 받는다 (D-14).
