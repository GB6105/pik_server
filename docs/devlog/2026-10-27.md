## 막힌 점·이슈
- 6-1 (수정된 사진 재분석)에서 사용자가 비용과 사진 변경 감지 방법을 물었다. iOS `assetContentChanged`는 앱이 실행 중일 때만 내용 변경을 구분하고, `PHPersistentObjectChangeDetails`는 변경 종류를 주지 않는다. Android `GENERATION_MODIFIED`도 내용 변경 구분이 문서에 없다. 선제 감지가 불가능해 벡터 비교 (B)를 골랐다가, 사용자가 재분석하지 않는 C로 바꿨다.
- 13-3 (지도 액션 장소 해석)에서 카카오 로컬 API는 결과 저장과 "API를 활용한 기능에 대한 별도 과금"을 금지한다. Pro 전용 기능이 별도 과금에 해당할 수 있어 카카오를 제외했고, 다른 앱 사례 (iOS 라이브 텍스트, Android Smart Linkify)를 따라 지도 앱 검색으로 연결하기로 했다.
- 장소 알림 (지오펜스)에는 좌표 저장이 필요해, 지도 액션과 분리해 Google Places (`place_id` 저장, 좌표 30일 캐시)로 결정했다.
- 이전 추천을 두 건 바꿨다. D-16 비로그인 이벤트는 단말 판단을 추천했었으나, 판단 로직이 서버·iOS·Android 3벌이 되는 문제로 '서버 판단, 단말 저장'으로 바꿨다. D-19는 실패 작업을 같은 행으로 되살리는 안을 추천했었으나, 이전 접수의 진행량이 바뀌는 문제로 '새 작업 행'으로 바꿨다.
- '접수마다 새 작업' 선택지는 SSOT의 "같은 사진·버전을 중복 접수하지 않는다"와 충돌해 선택지에서 뺐다.

## 결정
- [ADR-0024](../adr/0024-pre-implementation-decisions.md): 체험 칸 반환 없음, 비로그인 이벤트는 서버 판단·단말 저장, 별도 `action` 모듈, 실패·취소 버전 재접수는 새 작업 행, 서버 배치는 `SERVER_BATCH` 접수에 귀속, 벡터는 사진이 있는 동안 보관, 수정된 사진은 재분석 없음, 대표 삭제 시 벡터로 새 대표 선정, 3회 클릭은 대상별 1회, 웹 탐색은 단일 모델 (초기 Sonnet 5.5), 구매 직후 RevenueCat 재조회, 복원은 새 계정으로 이전, 장애 시 Pro 유지, 정리 상태만 동기화, 빈 이벤트는 항상 숨김, 모든 알림을 모든 기기로, 검색 호출 제한은 DB 카운터 + 429 `RATE_LIMITED`, 지도 액션은 지도 앱 검색, 번역은 서버 Claude Haiku, 장소 알림 좌표는 Google Places (사용자 결정)
- Claude 추천과 다른 사용자 결정: 벡터 보관 (추천: 보관 안 함), 수정된 사진 (추천: 서버가 벡터로 판단), 복원 동작 (추천: 활성 구독이 없을 때만 이전), 빈 이벤트 (추천: 원인별 처리), 알림 대상 기기 (추천: 이벤트만 모든 기기, 정리 독려는 마지막 사용 기기)

## 회고 메모
- 잘된 점: 결정마다 비용·약관·다른 앱 사례를 확인해 근거를 남겼다. 카카오 약관을 확인하지 않았다면 저장 금지 API를 지오펜스에 쓸 뻔했다.
- 문제: 지도 액션과 장소 알림이 모두 장소 해석을 쓰는데, 처음에는 한 항목으로 묶어 제시해 좌표 저장 요구를 놓쳤다. 사용자가 장소 알림을 물은 뒤에 분리했다.
- 교훈: 외부 API 선택지는 데이터를 저장하는 기능이 있는지부터 확인하고, 약관의 저장·과금 조건을 선택지 표에 함께 적는다.
