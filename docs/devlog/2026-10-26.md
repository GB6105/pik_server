## 막힌 점·이슈
- 사용자 목적은 "문서를 혼자만 참고하고 원격에 올리지 않기"였다. 확인해 보니 저장소가 PUBLIC이고 `docs/` 21개 파일이 이미 원격 `develop`에 공개돼 있어, 추적 해제만으로는 목적을 이룰 수 없었다. 이력 제거 + 저장소 재생성, Private 전환을 제시했고, 사용자는 docs·`.claude/docs`를 계속 올리기로 했다.
- zsh는 따옴표 없는 변수를 단어로 나누지 않아, 파일 목록 복사 스크립트가 목록 전체를 이름 하나로 처리했다. 복사는 0건이었고, `mkdir -p`가 만든 빈 디렉터리를 지웠다.
- ERD를 그린 뒤 설계 세션이 ADR-0017·0019를 확정해, 검색 (서버 실행 → 단말 실행)과 알림 (로컬 예약 → 서버 발송) 전제가 바뀌었다. 병렬 세션의 결정이 ERD에 늦게 반영됐다.
- `search_document`를 지울 때 `deletion_task.target`의 `SEARCH` 값을 놓쳤고, 다음 점검에서 고쳤다.
- erd-editor는 코멘트 길이만큼 테이블 폭을 늘려, 코멘트를 보강하는 사이 계정과 구독 그룹의 테이블이 겹쳤다. 그룹 배치를 다시 잡고 아래 그룹을 내렸다.

## 결정
- `docs/`·`.claude/docs/`는 계속 추적·공개한다 (사용자 결정). 기존 ADR-0001·0007 그대로라 새 ADR은 만들지 않았다.
- 재설치 판별 기록은 테이블 하나로 둔다. Android는 HMAC(ANDROID_ID)로 식별하고, iOS는 설치마다 행을 두고 DeviceCheck 비트로 판별한다 (사용자 결정).
- 제공자 사용자 ID 해시는 가입할 때 저장한다 (사용자 결정, Claude 추천은 탈퇴할 때만).
- 탈퇴 후 `revenuecat_event`에 `type`도 남긴다 (사용자 결정). ADR-0020의 최소 기록 목록보다 많아 ADR-0020 갱신이 필요하다.
- ER 공통 판단 6가지와 SSOT 보고 3건은 확정하지 않고 미결로 등록했다 (D-15·D-16). ER은 제안 단계라 ADR을 만들지 않았다.

## 회고 메모
- 잘된 점: 추적 해제 커밋을 push 전에 멈춰, 원격에는 아무 변경도 나가지 않았다.
- 문제: "gitignore에 docs 추가" 요청의 목적과 저장소 공개 여부를 확인하기 전에 실행 방식부터 정해, 커밋·이력 정리·되돌리기가 생겼다.
- 교훈: 저장소·파일을 숨기려는 요청은 먼저 목적과 공개 범위 (원격 공개 여부, 기존 이력)를 확인한다. 여러 파일을 다루는 스크립트는 Python으로 쓴다.
- 교훈 (ERD): 여러 결정에 기대는 산출물은 작업을 시작할 때 develop과 병렬 브랜치의 최신 ADR부터 확인한다. 테이블을 지울 때는 그 테이블을 가리키는 열거값·코멘트도 함께 검색한다.
