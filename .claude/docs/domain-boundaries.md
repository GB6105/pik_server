# 도메인 경계

근거: 요구사항 `# 데이터 경계와 후속 처리`. 테이블 수·서비스 분할은 미확정.

## 설계 원칙 (ADR-0024)
- 서버에서 해결할 수 있는 판단·처리는 서버에서 한다 (단말 2벌 구현 축소, 미정 정책을 서버 설정으로 조정)
- 예외: SSOT가 단말 저장을 요구하는 데이터 (비로그인 메모·태그·정리 상태·이벤트, FR-A-02), 단말 전용 FR, OS만 아는 사실 (권한·사진 변경 신호·지오펜스 진입)

## 도메인 후보
사진 연결 · 정리 · 분석과 검색 · 이벤트와 알림 · 계정과 구독 (+ 액션 모듈, ADR-0024)

## aggregate와 트랜잭션 경계
| 논리 단위 | 데이터 | 한 트랜잭션에 포함 |
|---|---|---|
| 사진별 Pik 정보 | photoId, 기기별 OS 연결, 메모·태그 관계, 버전 | 사용자 정보 + 갱신 의도 |
| 분석 작업·대표 묶음 | 접수 단위, 사진 버전, 작업 상태, 이용량 예약, 묶음·대표·구성·출처 | 작업 접수/결과 저장, 묶음 갱신. 전체 사진 잠금 금지 |
| 이벤트 | 이름·일정·구성 사진·완료/숨김·알림 버전 | 이벤트 변경 + 알림 무효화 의도 |
| 리마인드 | 대상·시점·예약 상태 | 리마인드 + OS 예약 의도 |
| 체험·이용 자격 | 체험 범위, 사진별 예약/완료, 클릭 수, 구독 권한 | 중복 검증된 사용량·권한 |
| 계정과 구독 | 제공자 연결·세션, 거래 검증 결과·유효 기간 | 인증 연결 또는 검증된 거래. 사진 동기화와 분리 |

- photoId(Pik)와 기기별 OS 사진 식별자는 별도 필드
- 기기 간 같은 사진 = iCloud 동기화 사진만 (PHCloudIdentifier). 다른 기기에 따로 저장된 사진은 별도 photoId (ADR-0022)
- photoId = 단말 생성 UUID. 소유 검증은 (주체, photoId) (ADR-0021)
- 묶음·대표 = 단말이 보낸 촬영 시각·유사도 벡터로 서버가 판단 (ADR-0021). 벡터는 사진이 있는 동안 서버 보관 (`photo_vector`, 비로그인은 P08 기한까지), 대표 삭제 시 벡터로 새 대표 선정·결과 이어 쓰기 (`INHERITED`) (ADR-0024)
- 수정된 사진 = 새 버전만 기록, 재분석·재묶음·재차감 안 함. 분석 중 버전이 바뀌어도 분석한 버전으로 결과 저장 (ADR-0024)
- 분석 접수 1건 = `analysis_request` (응답 작업 ID). `analysis_job` = 대표 사진 1장의 분석 호출 (ADR-0022)
- 재접수 판단은 사진 단위: 결과 있음 = 버전과 관계없이 기존 결과 반환·미차감, 진행 중 작업·미반환 예약 있음 (구성 사진 포함) = 기존 작업 ID, 최종 실패·취소·`INELIGIBLE`만 있음 = 새 작업 행. 서버 배치 작업도 접수 행 (`origin` = `SERVER_BATCH`)에 귀속 (ADR-0024)
- 비로그인 이벤트 = 단말이 보낸 기존 이벤트 요약으로 서버가 판단하고 저장은 단말. 판단 로직은 기존 이벤트를 입력받는 도메인 서비스 하나. 판단 API = 조회 (멱등 키·응답 저장 없음), `event` 모듈의 분석 완료 구독은 비로그인 주체를 건너뜀 (ADR-0024)
- 정리 상태 = 완료·정리 가능 시점만 서버 동기화, 세션은 단말 전용. `source_album_ref` = 전체 보관함 / iCloud 앨범 식별자 / 기기별 앨범 ID. 기기별 값은 재설치 때 D-20 이관 대상 (ADR-0024)
- 원본 삭제 = 사진 단위 상태. 권한 축소·다운로드 불가 = 기기별 연결 상태 (ADR-0022)
- OS 촬영·수정 시각과 Pik 처리 시각은 별도 필드

## 모듈 (ADR-0014, ADR-0023)
- Modulith 모듈 = 도메인 후보 + `shared` (ERD 그룹 '공통 인프라': 오류·멱등·로그·보안)
- 단계 2 = `shared`, `account` ('계정과 구독' 중 주체·설치·기기·토큰). 구독·이용량 경계와 나머지 모듈은 해당 단계에서 결정
- `action` 모듈 = 사진별 액션·웹페이지 후보·번역. `analysis`의 분석 완료 이벤트를 `action`과 `event`가 각자 구독 (ADR-0024)
- `consent` 모듈 = 외부 전송 동의 (`ai_consent`, ERD 그룹 '계정과 구독'). 다른 모듈은 `AiConsents.isGranted`로 전송 직전·결과 저장 직전에 확인, 철회 이벤트 없음 (ADR-0028)

## 스키마 공통 규칙 (ADR-0022)
- ER 설계안: `docs/erd/pik.erd.json` (erd-editor)
- 소유 주체 = `principal` (ACCOUNT / ANONYMOUS). 모든 `owner_id` → `principal.id`
- 단말 생성 ID = `client_ref` + UNIQUE(`owner_id`, `client_ref`). API `photoId` = `photo.client_ref`, 다른 테이블 `photo_id` = `photo.id`
- FK는 같은 모듈 안에만. 모듈 간은 ID만 저장
- `change_seq` = `owner_change_counter`를 같은 트랜잭션에서 갱신해 발급 (DB 시퀀스 금지)
- 동기화 root 삭제 = `deleted_at` tombstone. 분석 결과 이력 테이블 없음
- 동기화 대상·상태 변경 Pik 데이터 행 = `created_at`·`updated_at`·`version`. 추가·삭제만 하는 관계 행, 추가만 하는 기록, 인증·인프라 테이블은 예외
- 소유 범위 조회 인덱스 = `owner_id` 선두. 배치 폴링용 부분 인덱스, 외부 식별자·상위 행 조회 인덱스는 예외

## 내부 이벤트
| 트리거 | 후속 처리 |
|---|---|
| 메타데이터 변경 | 기존 분석에 반영 → 검색·추천·이벤트 갱신 |
| 분석 완료 | 출처 기록 → 액션·이벤트·검색 정보 반영. 재전달 시 중복 생성 금지 |
| 이벤트 수정·완료 | 알림 버전 갱신 → 기존 예약 무효화 → 허용 예약만 반영 |
| 검증된 구독 변경 | 이용 자격 갱신 → 신규 분석 허용/중단 → Pro 검색 범위 갱신 |

- 액션 생성과 이벤트 생성은 독립. 한쪽 실패가 다른 쪽을 막지 않음
- 완료·숨김·사진 제외된 이벤트는 늦은 분석 결과로 복구 금지
- 이벤트의 사진이 모두 빠지면 숨김, 숨기면 알림 버전 증가로 예약 무효. 기기별 재발송 직전에도 재확인 (ADR-0024)
- 내부 이벤트 = Spring Modulith event publication registry (JDBC outbox). 이벤트 브로커·조회용 DB 도입은 부하·유실 복구 요구 확인 후 결정 (ADR-0014)

## 배치
- 미분석 작업(Pro 처리량·우선순위), 허용된 실패 작업 재시도
- 서버 동기화 미완료분, 결과 확인 필요 작업
- 기한 도달한 리마인드·이벤트 알림, 정리 독려 (기기별 남은 대상)·권한 요청 발송 조건, 기기별 발송 행 재시도 (`notification_delivery`, ADR-0024)
- 플랫폼 구독 알림 누락·이용 기간 종료 재대조 (만료 미확인 구독은 RevenueCat 재조회, 확인 전까지 Pro 유지, ADR-0024)
- 이벤트 장소 좌표 30일 기한 전 `place_id`로 갱신. 대상 = 장소 알림 예약이 있는 ACTIVE 이벤트, 나머지는 기한에 좌표 삭제 (ADR-0024)
- 탈퇴 삭제 미완료분, 보관 기간 지난 임시 데이터
- 주기·재시도 횟수: P03·P08·P09 미정 → 설정값
